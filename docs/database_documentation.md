# PRISM — Database Architecture & Migration Documentation

**Database Engine:** MySQL Server 8.0+
**Target Schema:** `prism_ide`
**Migration Tool:** Alembic
**Current Alembic Revision:** `0004 (head)`
**ORM Framework:** SQLAlchemy 2.0+ (Declarative 2.0 syntax with type-annotated mapped columns)

---

## 1. Relational Database Schema Overview

The PRISM relational database maintains 24 production tables handling developer identities, tracking telemetry, skill knowledge graphs, adaptive mentoring dialogues, personalized task lifecycles, and audit logging.

## 2. Table Catalog & Detailed Schema

### 2.1 `developers`
Primary table storing developer identity, credentials, role, and active status.
- `id`: BigInteger, PK, auto-increment
- `developer_id`: String(64), unique, indexed
- `name`: String(128)
- `email`: String(255), unique, indexed
- `password_hash`: String(255), nullable
- `role`: String(32), default "developer"
- `is_active`: Boolean, default True
- `created_at` / `updated_at`: DATETIME(6)

### 2.2 `personalized_tasks`
Tasks generated by the Task Recommendation Engine.
- `id`: BigInteger, PK, auto-increment
- `task_id`: String(64), unique, indexed
- `developer_id`: String(64), FK -> `developers.developer_id` (CASCADE)
- `title`: String(256)
- `description`: Text
- `target_skill`: String(64), indexed
- `difficulty`: String(32), indexed
- `status`: String(32), default "generated", indexed
- `problem_statement`: Text
- `learning_objectives_json`: JSON
- `requirements_json`: JSON
- `test_cases_json`: JSON
- `hints_json`: JSON
- `expected_deliverables_json`: JSON
- `evaluation_criteria_json`: JSON
- `created_at` / `assigned_at` / `completed_at`: DATETIME(6)

### 2.3 `task_submissions`
Developer submissions against assigned tasks.
- `submission_id`: String(64), PK
- `task_id`: String(64), FK -> `personalized_tasks.task_id` (CASCADE)
- `developer_id`: String(64), FK -> `developers.developer_id` (CASCADE)
- `submission_type`: String(32), default "code"
- `source_code`: Text, nullable
- `file_tree_json`: JSON
- `repo_url`: String(512), nullable
- `explanation`: Text, nullable
- `status`: String(32), default "submitted"
- `submitted_at`: DATETIME(6), indexed

### 2.4 `task_evaluations`
Automated multi-stage AST evaluations of task submissions.
- `evaluation_id`: String(64), PK
- `submission_id`: String(64), FK -> `task_submissions.submission_id` (CASCADE)
- `task_id`: String(64), FK -> `personalized_tasks.task_id` (CASCADE)
- `developer_id`: String(64), FK -> `developers.developer_id` (CASCADE)
- `passed`: Boolean
- `score`: Float, 0.0 - 100.0
- `completion_status`: String(32), default "needs_revision"
- `strengths_json`: JSON
- `mistakes_json`: JSON
- `missing_requirements_json`: JSON
- `improvement_suggestions_json`: JSON
- `recommended_next_steps_json`: JSON
- `test_results_json`: JSON
- `feedback_message`: Text
- `evaluated_at`: DATETIME(6), indexed

### 2.5 `mentoring_conversations` & `mentoring_messages`
Interactive learning dialogues and individual turns.
- `mentoring_conversations`: `conversation_id` (PK), `developer_id` (FK), `task_id` (FK), `title`, `current_guidance_level`, `status`, `created_at`, `updated_at`.
- `mentoring_messages`: `message_id` (PK), `conversation_id` (FK), `sender_type` ("developer" or "mentor"), `content`, `guidance_level`, `created_at`.

### 2.6 `mcp_audit_logs`
Model Context Protocol audit trail.
- `log_id`: String(64), PK
- `tool_name`: String(64), indexed
- `caller_id`: String(64), nullable, indexed
- `input_summary`: String(512)
- `status`: String(32) ("success", "unauthorized", "validation_failed", "error")
- `duration_ms`: Float
- `timestamp`: DATETIME(6), indexed

## 4. Setup & Migration Commands

### Check Current Migration Status:
```bash
uv run alembic current
```

### Apply All Pending Migrations:
```bash
uv run alembic upgrade head
```

### Downgrade One Revision:
```bash
uv run alembic downgrade -1
```

### Seed Default Curriculum & Skills Graph:
```bash
uv run python -m prism.storage.seeder
```
